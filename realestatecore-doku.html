1. Was ist RealEstateCore?

RealEstateCore (REC) ist eine offene Ontologie für Gebäude und Immobilien, ursprünglich von Vasakronan, Akademiska Hus, ProNova Research, KTH und RISE entwickelt und heute von der RealEstateCore Consortium / Linux Foundation betreut. Sie beschreibt in OWL/RDF die Struktur von Liegenschaften, Räumen, technischen Anlagen, Sensoren, Verträgen und Akteuren sowie deren Verhältnis untereinander — maschinenlesbar und interoperabel.

Microsoft hat REC als Grundlage der Azure Digital Twins · Smart Buildings-Referenz gewählt, Siemens, Willow und grosse Immobiliengesellschaften (u.a. Vasakronan) setzen es produktiv ein. Damit steht mit REC ein in der Industrie getestetes, nicht-proprietäres Datenmodell zur Verfügung.

2. Warum REC für Real Estate 2.0

  • ✅ Kein Lock-in: offener Standard statt proprietäres Schema einer REM-Software.
  • ✅ End-to-End-Verknüpfung: Technik, Verträge, Finanzen, Nutzer im selben Graph abbildbar.
  • ✅ Algorithmen-ready: KI-Agenten können via SPARQL / GraphQL traversieren statt über SQL-Joins.
  • ✅ IoT-nativ: Sensoren / Observations sind First-Class-Citizens (nicht aufgepfropft).
  • ✅ Interoperabilität: Azure Digital Twins, Brick Schema, ifcOWL (BIM) lassen sich mappen.
  • ✅ Zukunftssicher: ESG- und Regulatory-Reporting profitieren von semantischer Konsistenz.

3. Kernklassen & Hierarchie

REC gliedert sich in fünf grosse Konzeptgruppen. Die für unser BOS relevanten Klassen:

Spaces (Räume & Container)
  • rec:Space // abstrakte Oberklasse
  • └─ rec:Site
  • └─ rec:Building
  • └─ rec:Storey
  • └─ rec:Apartment · rec:Room · rec:CommercialSpace
  • └─ rec:Zone // funktionale Zonen
Things (Anlagen, Komponenten)
  • rec:Asset · rec:BuildingComponent
  • ├─ rec:HVAC (Boiler, HeatPump, AHU…)
  • ├─ rec:Elevator · rec:Facade · rec:Roof
  • rec:Device
  • ├─ rec:Sensor (Temperature, Pressure, Meter…)
  • ├─ rec:Actuator
Agents (Personen & Organisationen)
  • rec:Agent
  • ├─ rec:Person · rec:Organization
  • ├─ Rollen: rec:Tenant, rec:Owner, rec:Contractor, rec:FacilityManager
Contracts & Documents
  • rec:Lease · rec:ServiceContract · rec:SalesContract
  • rec:Document (Plan, Invoice, Certificate…)
Observations (Zeitreihen)
  • rec:Observation // angelehnt an SOSA/SSN
  • ├─ Eigenschaften: rec:ofSensor · rec:hasValue · rec:atTime · rec:unit
  • └─ Messreihen werden in Time-Series-DB gespeichert, Metadaten im Graph

5. Konkretes Beispiel (Turtle)

Auszug aus dem Produktivgraph für Rosengasse 14, Whg. 3.02:

@prefix rec:  <https://w3id.org/rec#> .
@prefix re2:  <https://re20.ch/id/> .
@prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .

# Liegenschaft
re2:estate/rosengasse14 a rec:RealEstate ;
    rec:hasPart re2:bldg/rosengasse14 ;
    rec:owner   re2:agent/familyOfficeMueller .

# Gebäude mit Stockwerken
re2:bldg/rosengasse14 a rec:Building ;
    rec:grossArea "4820"^^xsd:decimal ;
    rec:hasPart re2:storey/rosengasse14-3 .

re2:storey/rosengasse14-3 a rec:Storey ;
    rec:level 3 ;
    rec:hasPart re2:apt/rosengasse14-3.02 .

# Wohnung
re2:apt/rosengasse14-3.02 a rec:Apartment ;
    rec:grossArea "82"^^xsd:decimal ;
    rec:roomCount "3.5" ;
    rec:orientation "south" .

# Mietverhältnis
re2:lease/L-1423 a rec:Lease ;
    rec:forSpace    re2:apt/rosengasse14-3.02 ;
    rec:hasTenant   re2:agent/keller-a ;
    rec:monthlyRent "2650"^^xsd:decimal ;
    rec:startDate   "2022-04-01"^^xsd:date ;
    rec:status      "active" .

# Technische Anlage + Sensor
re2:asset/boiler-01 a rec:HVAC , rec:Asset ;
    rec:locatedIn re2:storey/rosengasse14-ug ;
    rec:servesSpace re2:bldg/rosengasse14 ;
    rec:hasSensor re2:sensor/boiler-pressure .

re2:sensor/boiler-pressure a rec:Sensor ;
    rec:measures rec:Pressure ;
    rec:unit "bar" .

# Observation (Zeitreihe-Punkt)
re2:obs/2026-04-18T14:22:00 a rec:Observation ;
    rec:ofSensor re2:sensor/boiler-pressure ;
    rec:hasValue "2.8"^^xsd:decimal ;
    rec:atTime "2026-04-18T14:22:00Z"^^xsd:dateTime .

6. Validierung mit SHACL

Jede REC-Entität wird beim Schreiben gegen SHACL-Shapes validiert. Beispiel rec:LeaseShape: 

rec:LeaseShape a sh:NodeShape ;
    sh:targetClass rec:Lease ;
    sh:property [ sh:path rec:forSpace   ; sh:minCount 1 ; sh:class rec:Space ] ;
    sh:property [ sh:path rec:hasTenant  ; sh:minCount 1 ; sh:class rec:Agent ] ;
    sh:property [ sh:path rec:monthlyRent; sh:datatype xsd:decimal ; sh:minInclusive 0 ] ;
    sh:property [ sh:path rec:startDate  ; sh:datatype xsd:date ] .

Verletzungen erzeugen automatisch einen Klärungsfall in der Onboarding-Factory oder blockieren den Import (harte vs. weiche Constraints konfigurierbar).

7. CH-spezifische Erweiterungen

Wir ergänzen REC um ein schmales re2:-Namespace mit Schweiz-spezifischen Attributen, ohne das Kern-Schema zu brechen:

  • • re2:indexBaseMonth / re2:referenceRate — Schweizer Mietrecht (OR 269a/b).
  • • re2:geakClass (A–G) — GEAK/CECB-Gebäudeenergieausweis.
  • • re2:egid / re2:ewid — amtliche Gebäude-/Wohnungs-Identifikatoren (BFS).
  • • re2:qrIban — Schweizer QR-Rechnungs-IBAN an Lease/Invoice.
  • • re2:compliesWith rec:ArticleOR266a — Referenzen auf OR-Artikel.
